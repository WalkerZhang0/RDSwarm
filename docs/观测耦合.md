# 观测耦合：RDSwarm 的问题与研究路线

日期：2026-10-28。本文记录当前讨论形成的研究路线，不代表文中规划模块已实现。

同日实施更新：已接入独立 MobileNetVLAD ONNX CPU、自动 BF/PnP 编排及磁盘历史缓存，并完成 40 秒记录序列基线。实施细节与统计见 [GLOBAL_LOOP_BASELINE.md](GLOBAL_LOOP_BASELINE.md)。下表保留路线制定时的状态；GTSAM 增量融合和协方差验证仍待实施。

配套交互流程图：[研究路线.html](研究路线.html)。现有节点图：[RDSWARM_FRAMEWORK_FIGURE.html](RDSWARM_FRAMEWORK_FIGURE.html)。

## 1. 背景与当前目标

RDSwarm 采用各机独立运行的单目相机＋IMU VIO，计划通过机间视觉回环建立联系，并在每台机器的 GTSAM 后端中维护本机获得的状态和观测。研究目标是依据相对状态不确定性选择检索、特征请求和几何验证等动作，在定位质量与计算、通信成本之间作出有效取舍。

当前主线是完成一个可验证、可复现的算法平台：VIO 发布关键帧；回环侧独立计算 MobileNetVLAD 全局描述子并检索候选；利用 SuperPoint 局部描述子、BF ratio＋互检和 PnP 验证候选；记录接受与拒绝原因，再逐步接入 GTSAM 和长期评估。先固定 BF 为局部匹配基线，LightGlue 保留为后续对照变量。

MobileNetVLAD 归属于回环侧的独立异步模块，由 VIO 正式发布的关键帧触发。本机图像传递仍有复制、缓存和排队成本，机间只交换摘要及候选确定后请求的局部特征。当 VIO 持续输出普通帧但长时间没有关键帧时，按采样时间阈值触发非关键帧搜索，并记录触发原因；阈值尚待实验确定。非关键帧搜索结果需要在实际约束端点上重新验证，不能直接迁移成附近关键帧的回环测量。

## 2. 当前实现与验证边界

| 内容 | 当前状态 | 可以支持的结论 |
| --- | --- | --- |
| 独立单目 VIO、原生关键帧导出 | 已有代码与运行记录 | 可以提供带身份、采样时间及部分有效三维点的关键帧 |
| SuperPoint CPU 描述与邻机二维增补 | 已实现，已有少量固定帧对测试 | 可以检查特征身份和局部几何链路 |

| LightGlue ONNX CPU | 已有离线探针 | 作为后续对照；当前主线使用 BF |
| 全局描述子索引 | 已有 CPU cosine Top-K | 需要真实的全局描述子生产与摘要交换才能评估检索 |

| GTSAM 后端 | 当前为 Pose3 契约及输入校验 | 尚无 iSAM2 状态融合和有效联合协方差查询 |

VIO 当前默认配置仍为 Shi-Tomasi 检测＋KLT 跟踪；可选 SuperPoint 分支只替换新点检测。回环描述节点在 VIO 轨迹的当前像素处采样 SuperPoint 描述子，并追加独立二维 SP 点。因此“使用 SP 描述子”不等于“整个 VIO 前端已经替换成 SP＋LG”。长期实验应记录并固定这项配置。

## 3. 观测之间为什么存在耦合

单目视觉不能从一张图像独立恢复米制深度。当前用于 PnP 的本机三维点来自视觉惯性轨迹及多视角估计，邻机提供二维观测。简写为：

\[
\hat P_A=f(z_A,u_A),\qquad
\hat T_{AB}=g(\hat P_A,z_B),
\]

其中 \(z_A\) 是本机历史视觉观测，\(u_A\) 是本机 IMU 数据，\(z_B\) 是邻机视觉观测。邻机观测带来新的机间信息，同时 PnP 输出继承了本机地图点误差；如果邻机 VIO 也使用了 \(z_B\)，回环还可能与邻机运动估计共享信息。

“出现共享信息”不等于“所有回环都是重复观测”。风险是把这些压缩估计之间的误差视为完全独立，并给出不合理的小噪声，导致后端过度自信。重新在同一图像提取特征、改变匹配器或将地图点固定，都不会自动证明独立性；独立提取可以改变直接共享的轨迹，但原始数据、标定和位姿依赖仍需分析。

需要区分三种相关性：

1. **状态之间的相关性**：同一图中多个位姿共享运动、回环和先验，由联合协方差中的交叉块表达。
2. **新测量误差与已有状态/测量误差的相关性**：VIO 地图点被 PnP 复用，或邻机二维观测已进入其 VIO。单独查询状态联合协方差不会自动恢复这部分依赖。
3. **多条回环及多节点信息之间的相关性**：相邻回环共享地图点；同一测量被转发、重复接入或被包含在邻机后验中再次融合。观测 ID 去重能处理完全重复的记录，但不能消除部分共享数据的统计相关性。

按当前描述，双目回环可以在模块内重新三角化，减少对 VIO 历史尺度和位姿的依赖；若共享图像、特征或标定，仍不能仅凭“双目重新构点”认定严格独立。本文不以尚未核验的 Omni-swarm 上游实现作为独立性证明。

## 4. 联合协方差需要处理到什么程度

GTSAM 能根据输入的因子、噪声、先验和线性化点计算当前图模型下的联合边缘协方差。它不会自动识别两个独立噪声因子内部共享了原始图像或 VIO 估计。

对于相对位姿 \(T_{AB}=X_A^{-1}X_B\)，在一致的 Pose3 切空间约定下：

\[
P_{AB}=\begin{bmatrix}P_{AA}&P_{AB}^{\mathrm{cross}}\\
P_{BA}^{\mathrm{cross}}&P_{BB}\end{bmatrix},\qquad
P_{\mathrm{rel}}\approx J P_{AB}J^\top.
\]

\(J\) 是相对位姿函数的 Jacobian；需记录左右扰动、坐标系及旋转/平移单位。不能将完整 Pose3 的传播简单替换为两个边缘协方差相加。

如果候选线性测量的误差与先验误差独立，常用更新为：

\[
P^+=P-PH^\top(HPH^\top+R)^{-1}HP.
\]

如果定义 \(e=x-\hat x\)、创新 \(r=He+v\)，且 \(C=\operatorname{Cov}(e,v)\ne0\)，则在线性高斯模型下需要：

\[
S=HPH^\top+HC+C^\top H^\top+R,\qquad
P^+=P-(PH^\top+C)S^{-1}(HP+C^\top).
\]

这里的 \(C\) 与两个位姿间的交叉块不是同一个量。普通独立噪声因子不会自动代入 \(C\)，是否采用联合因子、信息归属或保守融合，需要进一步设计。上述公式用于说明依赖关系，不是当前已经实现的更新接口。

首版应保留与目标相对状态有关的联合块，不需要每次输出整个历史图的稠密协方差。单个节点只能报告给定其实际已接收信息的局部后端协方差，不能把它称为所有节点信息汇总后的全局后验。

## 5. 当前处理思路：推进主线，同时留下可验证的分支

### 5.1 主线：完成可验证算法平台

1. 固定 VIO 配置、SP 模型、标定、BF/PnP 门限和数据时间范围，保存可复现输入。
2. 在回环侧接入真实 MobileNetVLAD，按 VIO 关键帧异步推理、交换摘要并生成跨机 Top-K 候选；完成非关键帧超时搜索的身份与端点规则。
3. 打通候选→描述→请求→BF→PnP→接受/拒绝的自动流程。局部描述子每帧只计算一次，按需计算与缓存策略应显式配置。
4. 增加持久化或有界工作集、队列统计、失败重试和重复约束控制，保留检索历史可查询性。有界 RAM 不应等价于无记录地删掉历史检索机会。
5. 实现 GTSAM 状态、VIO 运动因子、回环接入和查询；固定 gauge，正确连接初始独立的各机坐标系。尚未相连的机间相对状态应标为不可查询，不能返回伪有限协方差。
6. 先完成长序列观测与估计基线，统计候选、几何通过结果、误差、耗时、字节数、排队和丢弃情况，再进入协方差调度对照。

回环前端统计可以先于 GTSAM 融合完成；声称定位改善、协方差可信或调度有效，则需要相应的后端和独立评估。GT 仅用于评估，不参与候选生成、在线初始化或选择。

### 5.2 分支：观测耦合与协方差可信度

主线现在就记录：`FrameKey`、两端真实采样时间、session/epoch、相机/标定及模型身份、匹配 feature_id、三维点来源、观测 ID、已使用的因子来源、噪声来源、后端版本。现有 `source_observation_ids` 是起点，还不足以描述三维点形成所依赖的全部历史轨迹。

初期采用明确标记的松耦合噪声假设：VIO 运动因子和 PnP 回环先使用可配置噪声，配置值标记为“暂定/未校准”。当前 `covariance_valid=false` 不应被静默改成“已估计”；若为后端试验使用名义噪声，需在日志中保留其来源和近似。

对 PnP 噪声的校准是指：在独立参考数据上，用一致的 SE(3) 误差定义检验 \(R_{\mathrm{loop}}\) 是否合理。可比较固定噪声和依赖深度、覆盖率的模型，并做参数敏感性分析。校准集与最终评估集应分开。对称重投影误差小、Hessian 可逆或放大噪声，都不能单独证明统计一致性。

相邻回环共享三维轨迹时，要检查观测收益是否被重复高估；也要分析 VIO 增量之间的时间相关性，不能只检查回环噪声。鲁棒核用于缓解外点，不能代替相关性建模。

### 5.3 两条路径在调度实验前汇合

“协方差随时间平稳”“加入因子后数值下降”是诊断量，不能作为可信性验收。需要检验：

- 模型预测的不确定性与独立参考下的实际误差是否匹配；有完整参考时，在适当 gauge 和误差坐标下检查覆盖率或 NEES/NIS，并说明线性化和选择偏差限制。
- 预期收益较大的观测是否更能改善目标状态；在评估时处理噪声观测可能偶然恶化点估计的情况，使用重复实验与总体统计。
- 更换合理噪声设置、共享观测比例和缓存/候选预算后，调度排序与总体收益是否稳定。
- 每种调度策略是否维护自己的信息集和后端状态，是否真实跳过了对应计算/通信；不能使用全量方案后验代替各策略运行。

若近似不能支撑目标结论，则进入更完整的联合建模：显式共同地标、Smart Factor、MSCKF 风格结构消元、相关子图摘要或保守融合等候选方案。MSCKF 的左零空间投影用于消除地标增量，不会自动消除状态与测量的相关性；边缘化也必须保留生成的相关先验。

## 6. 当前数据能验证什么

目前检查的是本地 S3E 导出 GT 文件：Alpha/Carol 姿态列恒为单位四元数，不能确认其提供了可用姿态；这不等价于认定 S3E 所有原始数据都没有姿态参考。GT 位置参考点到 IMU/body 的杆臂尚未确认，时间插值还需限制缺口并保留端点记录。

因此目前可报告位置参考点间距与回环平移模长的差，并明确二者参考点可能不同；不能据此校准完整六维回环噪声。接近零基线时相对百分比会失真，应同时报告米制绝对差。空间接近也不能直接作为视觉可匹配的真回环标签，需结合共视证据或人工审查，处理重复纹理和方向差异。

完整旋转、平移方向和六维协方差验证需要可靠姿态、时间及外参参考。合成数据可先检验 Jacobian、相关噪声传播和坐标约定；真实完整参考数据用于检验模型适用性。

## 7. 决策与下一步

当前优先任务仍是 MobileNetVLAD＋SP/BF/PnP 的可复现长序列平台，继而完成 GTSAM 融合。观测耦合分支现在启动来源记录与误差诊断，后续依据证据选择噪声校准、相关性近似或联合建模的深度；它是协方差调度结论成立的验证条件。

下一次讨论聚焦 MobileNetVLAD 的模型来源、预处理、独立异步节点和关键帧/超时触发，不在本文中预设未经验证的权重、阈值或性能收益。
